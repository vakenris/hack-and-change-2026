# HackChange — юридический ассистент ПСБ

## Цель MVP

- Веб-чат и `solution.py` используют одно ядро из `assistant_core/`. Чат передаёт историю диалога и открывает карточку источника по ID. Сабмит отвечает на каждый тест-кейс независимо.
- Основание юридического вывода — применимое положение из выданной базы. Каталог SQLite и индекс FTS5 готовятся заранее. Цитаты и координаты берутся из каталога, который хранит дословный текст TXT.
- Проверяй редакцию на дату нужного события. При нехватке сведений показывай подтверждённую часть, запрашивай конкретный факт или объясняй причину отказа. Технический сбой передавай через `TechnicalError`.

## Границы блоков

| Блок | Зона ответственности |
| --- | --- |
| Фронтенд | Чат, история, состояния и просмотр источников в `frontend/`. |
| Данные | Разбор TXT, каталог, поиск и выбор редакций. Входы и сборки в `data/raw/` и `data/processed/`. |
| ML | Клиент модели, промпты, смысловая проверка, политика ответа и оценка. Используй `$hackchange-llm`. |
| Интеграция | Общие контракты, оркестрация и проверка ID в ядре, FastAPI, `solution.py`, упаковка и запуск. |

## Работа над задачей

1. Сверь запрос с существующими файлами и согласованной областью правок. Для стыков начинай с `assistant_core/contracts.py` и `assistant_core/assistant_service.py`. Изменения общих контрактов согласовываются с командой.
2. Пользуйся актуальными импортами репозитория. Для новых частей MVP сверяй назначение модулей с планом команды. Формат сабмита и настройки платформы сверяй с техрегламентом и образцами организаторов, когда они доступны.
3. Проверяй затронутый сценарий через его штатную точку входа. Для проверки стыков используй `ASSISTANT_STUB=1`. Для проверки реального поиска или LLM используй соответствующую реализацию и отдельно фиксируй недоступные проверки.
4. Храни ключи API в окружении. Для разработки и проверки используй выданную базу и тестовые или выдуманные персональные данные.
